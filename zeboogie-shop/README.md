# Zeboogie — интернет-магазин на товарах сообщества ВКонтакте

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Zod · Lucide.
Из VK берутся **только товары** (название, описание, цена, фото, подборки). Интерфейс, тексты бренда (`src/content/brand.ts`) и дизайн — собственные.

## Быстрый старт
Нужен Node.js 20.9 или новее (рекомендуется 22 LTS) и npm.

**macOS / Linux**
```bash
cd zeboogie-shop
npm install
cp .env.example .env.local      # по умолчанию VK_MODE=demo
npm run dev                     # http://localhost:3000
```

**Windows (PowerShell)**
```powershell
cd zeboogie-shop
npm install
Copy-Item .env.example .env.local   # в cmd.exe: copy .env.example .env.local
npm run dev                         # откройте http://localhost:3000
```

Боевой запуск: `npm run build`, затем `npm start` (порт 3000; другой порт — `npm start -- -p 3100`).
Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.

### Открыть сайт с телефона (Windows, macOS, Linux)
1. Телефон и компьютер — в одной сети Wi-Fi. Запустите `npm run dev` (или `npm run build` → `npm start` — этот вариант самый близкий к боевому).
2. Узнайте адрес компьютера: Windows — `ipconfig` (строка «IPv4-адрес», например `192.168.1.50`); macOS/Linux — `ifconfig` / `ip a`.
3. На телефоне откройте `http://192.168.1.50:3000`. Если Windows спросит про брандмауэр — разрешите доступ для Node.js в частной сети.
4. Адреса домашних сетей (`192.168.*.*`, `10.*.*.*`, `172.16–31.*.*`, `*.local`) уже разрешены в `next.config.ts`. Туннель или своё имя хоста добавьте так: `DEV_ALLOWED_ORIGINS=my-tunnel.example.com npm run dev` (PowerShell: `$env:DEV_ALLOWED_ORIGINS="my-tunnel.example.com"; npm run dev`).

> Почему это важно: Next.js 16 в режиме `npm run dev` по умолчанию не пускает к «служебным» ресурсам (в том числе к WebSocket горячей перезагрузки) никого, кроме `localhost`. Страница с телефона рисовалась, но React не запускался — все кнопки были «мёртвыми». Теперь это настроено; в боевой сборке (`npm start`) проблемы не было и нет.

## Дизайн-система
Весь стиль живёт в **одном файле — `src/styles/tokens.css`**: цвета, шрифты, шкала отступов, радиусы, тени, тайминги анимаций, ширина контента, высота шапки. Меняете значение — меняется весь сайт.

| Что меняем | Где |
|---|---|
| Палитра (`--bg`, `--surface`, `--border`, `--text`, `--text-soft`, `--moss`, `--copper` …) | `tokens.css`, блок `:root` |
| Шрифты | `tokens.css` (`--font-ui-stack`, `--font-display-stack`) и `src/styles/fonts.css` (подключаются только кириллица и латиница) |
| Отступы 8 / 16 / 24 / 40 / 64 / 96 px, ширина контента ≈1280 px | `--space-1…6`, `--section-y`, `--container` |
| Радиусы 4 / 6 / 8 px, тени, тайминги (`--ease`, `--dur-hover`, `--dur-appear`, `--stagger`) | `tokens.css` |
| Размеры заголовков (`text-display`, `text-h1…h3`, `text-lead`) | `tokens.css`, блок `@theme` |
| Готовые компоненты и анимации | `src/styles/*.css`: `base` (сброс, фокус, touch) · `ui` (кнопки, поля, «таблетки», аккордеон, ползунок, шторки) · `header` (шапка, вкладки, меню, нижняя панель) · `hero` · `card` (сетка, карточки, ленты) · `catalog` · `product` · `cart` (корзина, оформление) · `motion`; `src/app/globals.css` лишь подключает их |
| Раскладка: высота шапки, демо-плашки, нижней панели, пропорции обложки, зоны нажатия | `tokens.css`: `--header-h`, `--banner-h`, `--bar-h`, `--card-ratio`, `--hit`, `--hit-gap`, безопасные зоны `--safe-*`, слои `--z-*` |

Палитра: фон `#F1EAE0`, плашки `#E8DFD1` с рамкой `#D9CDBB`, текст `#2E2620`, мох `#5E6B4A`, медь `#A47551`. Чистых белого и чёрного нет.
Отличия от исходных значений: вторичный текст `#6B5F54` вместо `#7A6E62` (исходный даёт 4,2:1 — ниже AA), для текста и hover-заливок используется более тёмная медь `#865634` (исходная `#A47551` остаётся для линий, иконок и крупных заголовков). Контраст всех пар проверен расчётом.

**Анимации** — только `transform` и `opacity` (плюс цвет у кнопок и ссылок), всё отключается при `prefers-reduced-motion`:
- появление блоков при прокрутке на `IntersectionObserver` с каскадом 70 мс — `src/components/ui/Reveal.tsx` (сервер отдаёт блоки видимыми, без JS всё читается);
- шапка сжимается при прокрутке вниз и возвращается при прокрутке вверх — `HeaderFrame.tsx` + CSS `.site-header` (высота в потоке не меняется, раскладка не «прыгает»);
- карточка: подъём, зум фото 600 мс, сердечко с «пульсом»; кнопка «В корзину» с подтверждением; счётчики в шапке «подпрыгивают»;
- корзина выезжает как `<dialog>` (`translate` + `@starting-style`), галерея — плавный crossfade;
- переходы между страницами: нативные View Transitions (`app/template.tsx`) с CSS-фолбэком для браузеров без поддержки;
- фото проявляются после загрузки (песочная заглушка с мерцанием), первый экран грузится с `fetchpriority="high"`.

## Что где на сайте
- **Шапка**: логотип, вкладки «Каталог ▾» (выпадающая панель с подборками и крупными фото), две самые большие подборки, «О мастерской», «Доставка и оплата», «Контакты»; иконки поиска, избранного и корзины со счётчиками; сжимается при прокрутке. Какие подборки выносить во вкладки — `brand.nav.mainCategories` в `src/content/brand.ts`.
- **Телефон**: бургер открывает полноэкранное меню; внизу панель быстрых действий (каталог, поиск, избранное, корзина) в зоне большого пальца; на странице товара вместо неё — панель «♡ В корзину».
- **Главная**: hero с 3–5 лучшими работами → плитки подборок → новые работы → «О мастерской» → преимущества → «В интерьере» (если мастерская отметила такие снимки) → подписка (сообщество ВКонтакте).
- **Каталог**: сетка 2 / 3 / 4 колонки, «таблетки» подборок, счётчик, фильтры (подборка, цена с ползунком, формат, наличие — по данным), сортировка, вид «обычные / крупные», выбранное — чипами со «Сбросить всё»; фильтры и сортировка в адресе страницы; «Показать ещё»; при возврате из товара возвращаются страницы и прокрутка.
- **Товар**: на десктопе первый экран целиком (галерея слева, цена и покупка справа, аккордеоны «Описание / Размеры и материал / Доставка и оплата / Уход»), на телефоне — фото со свайпом, название, цена и закреплённая панель покупки; «О материале», «Похожие работы», «Вы смотрели».
- **Корзина** выезжает справа при добавлении; страница `/cart`; оформление `/checkout` — три шага (контакты → доставка → оплата), итог всегда на виду.

## Витрина: обложки, hero и порядок фото (`src/content/curation.*.json`)
Какое фото показывать первым, как его кадрировать и какие работы вынести в hero, хранится **отдельно от данных VK и от самих файлов**: исходные фото не переименовываются и не перезаписываются, меняется только порядок и подсказки для вёрстки. Ключ записи — id товара VK (для демо — `2000 + номер`).

| Поле | Что делает |
|---|---|
| `cover` | номер фото (с 1), которое станет обложкой; остальные сохраняют порядок |
| `hover` | второе фото в каталоге при наведении мыши |
| `focalPoint` | точка кадрирования обложки в рамке 4:5 (`object-position`) |
| `featured`, `featuredOrder` | работа в hero на главной и её место |
| `collectionCover` | обложка подборки (плитки на главной, меню «Каталог») |
| `badges` | `"last"` («Последний экземпляр»), `"preorder"` («Под заказ») — только вручную; «Новинка» ставится сама для работ младше 30 дней |
| `interior` | снимки «в интерьере» для главной |
| `reshoot` | заметка «нужно переснять» (на сайте не видна) |

Для живого сообщества — `curation.live.json`, тот же формат. Откат: удалить запись — порядок фото вернётся к исходному. После правки файла демо-снимок каталога пересобирается сам.

## Адаптивность и доступность
- Проверено на 360×640, 390×844, 430×932, 768×1024, 1366×768 и 1920×1080: горизонтальной прокрутки нет, ничего не обрезается, зоны нажатия ≥ 44×44 с зазором ≥ 8 px.
- Эффекты наведения включаются только для мыши — `(hover: hover) and (pointer: fine)`; на касании у каждой кнопки заметное `:active`. Закрытые панели и окна — `visibility: hidden` / `display: none` (нативный `<dialog>`), поэтому невидимое ничего не перехватывает.
- Семантическая вёрстка, настоящие `<button>`/`<a>`, `role="tablist"` у точек hero и галереи, `aria-expanded` у меню, вкладок и аккордеона; клавиатура: стрелки (hero, подборки, ползунок цены, галерея), Enter/Space, Esc закрывает меню, поиск, корзину, просмотр. У всех картинок `alt` (декоративные дубли — пустой), контраст AA, видимый фокус, `prefers-reduced-motion`.
- axe-core (WCAG 2.0/2.1 A+AA и best-practice): 0 нарушений на всех страницах и во всех окнах (меню, фильтры, поиск, каталог-выпадашка) на телефоне и десктопе.
- Lighthouse на production-сборке (`npm run build && npm start`, медиана трёх запусков, эмуляция Moto G Power на медленной 4G): телефон — главная 86 (разброс 83–88), каталог 94, карточка товара 90; десктоп — главная 100. Доступность и Best Practices — 100 везде, CLS 0. Главная на телефоне держится около 86–88, потому что её первый экран — большое фото hero, а исходные фото каталога узкие (540 px): для чёткого и быстрого hero нужны оригиналы от 1600 px (см. `docs/covers.md`). SEO ниже 90 только из-за демо-режима: он намеренно закрыт от индексации (`noindex`); в режиме `VK_MODE=live` страницы индексируются.

## Демо- и рабочий режим
| `VK_MODE` | Источник | Хранилище |
|---|---|---|
| `demo` (по умолч.) | `src/lib/vk/demo/market.json` — **тестовые** данные в формате ответов VK API (28 товаров: названия, цены и фото — из выгрузки каталога владельца от 11.10.2026; подборки условные) | `data/catalog.demo.json` |
| `live` | VK API | `data/catalog.vk.json` |

Файлы снимков разные, поэтому демо-товары **никогда не смешиваются** с реальными. В демо-режиме сайт показывает плашку, закрыт от индексации (`noindex`, `robots`, пустой sitemap).

## Подключение сообщества
1. Получите токен (любой один из вариантов):
   - **Ключ сообщества**: Управление → Настройки → Работа с API → Ключи доступа, право **«Товары»** (и «Сообщения» для автоотправки заказов);
   - **Сервисный ключ** VK-приложения (достаточно для чтения публичных товаров).
2. В `.env.local`:
   ```
   VK_MODE=live
   VK_GROUP=zeboogie
   VK_ACCESS_TOKEN=...
   SITE_URL=https://ваш-домен
   SYNC_SECRET=<openssl rand -hex 32>
   ```
3. В сообществе должен быть включён раздел «Товары».
4. `npm run sync` — первая загрузка (если снимка нет, она произойдёт и автоматически при первом открытии сайта).

> Модуль VK написан по документации (`groups.getById`, `market.get`, `market.getAlbums`, `messages.send`) и проверен на подменённом `fetch`, но **с реальным сообществом не запускался** (в среде разработки VK был недоступен). Поля `variants`/`albums_ids` разбираются терпимо и подтверждаются только на живых данных.

## Синхронизация
- Первая загрузка: автоматически или `npm run sync`.
- Обновление: фоново при открытии сайта, если снимок старше `SYNC_TTL_MINUTES` (stale-while-revalidate), и по расписанию: `curl -X POST -H "Authorization: Bearer $SYNC_SECRET" https://домен/api/sync` (cron/планировщик).
- Новые товары добавляются, изменённые обновляются, дубли исключены (ключ `owner_id_item_id`). Товары, исчезнувшие из VK, помечаются `removed` (страница показывает «больше недоступна», в каталоге/sitemap их нет); вернувшиеся восстанавливаются. Пустая выдача VK при непустом каталоге **не стирает** товары.
- Лимиты VK: запросы идут по очереди (≤3/с), при кодах 1/6/9/10, таймаутах и 5xx — повтор с экспоненциальной паузой. Журнал: `data/sync-log.jsonl` + JSON-логи в stdout (секреты маскируются).

## Заказы
Магазин не принимает оплату. Заказ — это сообщение сообществу:
- Сайт проверяет наличие позиций по каталогу и собирает текст заказа.
- Если задан `ORDER_NOTIFY_VK_USER_ID` и ключ сообщества с правом «Сообщения» — сервер отправляет сообщение сам, и только после ответа VK сайт пишет «Заказ отправлен».
- Иначе сайт честно пишет «заказ подготовлен, но **не отправлен**» и даёт текст + ссылку на сообщения сообщества. Корзина очищается только после подтверждения покупателем.
- Онлайн-оплата не реализована (нужен внешний платёжный сервис).

## Переменные окружения
См. `.env.example`. Секреты (`VK_ACCESS_TOKEN`, `SYNC_SECRET`) используются только на сервере; префикса `NEXT_PUBLIC_` нет, в клиентском бандле их нет (проверено поиском по `.next/static`).

## Структура
```
src/app/            страницы и API (/, /catalog, /product/[slug], /cart, /checkout, /favorites, /about, /delivery, /contacts, /api/*)
src/components/     ui (Reveal, ProductImage, Price …), layout (шапка, меню, поиск, нижняя панель), home, catalog, product, cart, checkout
src/styles/         tokens.css (дизайн-токены), fonts.css и файлы стилей по разделам
src/app/template.tsx  переходы между страницами (View Transitions)
src/lib/vk/         client (лимиты/повторы), api, schemas (zod), mapper, source (demo|live), messages
src/lib/catalog/    sync, diff, store (файловый снимок), query (фильтры/сортировка/поиск), service (чтение для UI)
src/content/        тексты бренда (не из VK) и слой витрины curation.*.json
vk-mcp/             (в корне репозитория) необязательный MCP-сервер для чтения товаров VK из Claude
```
Хранилище — файловый снимок за узким интерфейсом (`store.ts`). Для нескольких серверов/serverless замените реализацию на PostgreSQL (Prisma) — остальной код не меняется. Prisma/PostgreSQL здесь намеренно не подключены: для одного сервера они избыточны.
